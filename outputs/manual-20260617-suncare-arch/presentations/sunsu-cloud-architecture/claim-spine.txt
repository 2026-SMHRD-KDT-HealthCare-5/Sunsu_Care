Thesis:
Sunsu Care should be deployed as a segmented cloud architecture where the public surface is small, AI analysis runs privately, and image/data flows are auditable.

Audience:
Class presentation / architecture review for a React, Node, FastAPI AI web service.

One-line arc:
Start from the class React+Node architecture, then show how Sunsu Care adds AI workers, object storage, managed MySQL, external OCR/LLM APIs, security boundaries, and an operations roadmap.

Slides:
1. Claim: The class architecture becomes a production-ready AI analysis platform when the AI and data planes are separated.
   Proof object: deck title with architecture scope rail.
2. Claim: Sunsu Care adds an AI analysis plane and callback loop to the basic React+Node web pattern.
   Proof object: before/after architecture comparison.
3. Claim: The target cloud design keeps only the load balancer public while app, AI, and data tiers stay private.
   Proof object: VPC deployment diagram.
4. Claim: Image analysis is asynchronous, so the user flow must separate upload acceptance from AI completion.
   Proof object: numbered sequence flow.
5. Claim: Security depends on network segmentation plus token-based service-to-service control.
   Proof object: trust boundary map.
6. Claim: Each data store has a narrow responsibility so uploads, analysis, cache, and model artifacts do not mix.
   Proof object: storage responsibility matrix.
7. Claim: The first deployment can run on Docker servers, then graduate to Kubernetes and queue-backed AI workers.
   Proof object: phased roadmap.
